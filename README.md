# Real Estate & Mortgage Analytics Capstone

## Project Overview

This archived capstone analyzes U.S. geographic, housing, mortgage, income, and demographic data in a banking and mortgage analytics scenario. It combines data preparation, exploratory data analysis, geographic analysis, feature engineering, factor analysis, regression modeling, and Tableau reporting. It is a learning project, not a production banking system.

## Business Problem

The project explores mortgage-backed and real-estate trends across geographic areas. Its analytical tasks compare family income, rent, home ownership, mortgage costs, and household debt-related indicators; model monthly mortgage and owner costs; and communicate the analysis through a dashboard.

## Dataset

The tracked training and test CSV files contain geographic observations and variables covering:

- geographic identifiers and population;
- household and family income;
- rent, mortgage, and homeowner costs;
- second mortgages, home equity, debt, and home ownership;
- education and age demographics; and
- marital-status indicators.

The notebook treats `UID` as the observation identifier and sets it as the index during preparation. The original external data source is not explicitly documented in this archived project repository.

## Analysis Workflow

### Data preparation

The notebook:

- loads the training and test datasets;
- inspects shapes, columns, and descriptive statistics;
- identifies `UID` as the index;
- examines missingness and uses mean imputation for numerical missing values;
- inspects feature variance; and
- removes `BLOCKID` and `SUMLEVEL` from the working datasets.

### Debt and housing analysis

The analysis identifies locations with relatively high second-mortgage prevalence, maps geographic results with Plotly, and derives a `bad_debt` feature. It also creates debt-related pie charts, compares debt indicators for selected cities, and examines household and family income distributions.

### Demographic analysis

The notebook explores population distributions, engineers population-density and median-age fields, creates population bins, and analyzes marital-status indicators. It also compares rent with family income and examines correlations among selected variables.

### Factor analysis

Factor analysis is applied to numerical features to explore possible latent relationships. The archived workflow does not establish that the resulting factors were fully validated or statistically interpreted.

### Regression modeling

A Scikit-learn Linear Regression model predicts `hc_mortgage_mean`, the mean monthly mortgage and owner costs for a geographic observation. Predictor groups include geographic identifiers, population, family income, mortgage and debt measures, education, age, ownership, and marital-status indicators.

## Modernized Modeling Workflow

The repository now also contains [`notebooks/real_estate_modeling_modernized.ipynb`](notebooks/real_estate_modeling_modernized.ipynb), a focused companion to the historical notebook. It does not present the newer workflow as part of the original capstone. Instead, it documents a later methodological review and implements:

- numeric missing-value imputation and scaling inside a Scikit-learn `Pipeline`;
- categorical imputation and one-hot encoding with unknown-category handling;
- training-only fitting, including fold-local preprocessing during cross-validation;
- explicit removal, rather than imputation, of missing target values;
- a train/holdout integrity audit for shared UIDs and identical predictor rows;
- an explainable feature review that treats `STATEID` as categorical and excludes continuous interpretations of `COUNTYID` and `zip_code`;
- a `DummyRegressor` baseline and comparison with Linear Regression, Ridge, and Random Forest models;
- reproducible five-fold model comparison using R², RMSE, and MAE;
- selection based only on training cross-validation followed by one final holdout evaluation;
- residual, largest-error, transformed-feature interpretability, and state-level holdout diagnostics; and
- reusable helpers in [`src/modeling.py`](src/modeling.py) with lightweight synthetic-data tests in [`tests/test_modeling.py`](tests/test_modeling.py).

The executed modern notebook writes its verified cross-validation results to `reports/model_comparison.csv`, its primary state diagnostics to `reports/state_metrics.csv`, and its holdout robustness check to `reports/holdout_sensitivity.csv`; the committed reports were generated by that run rather than entered manually.

### Modernized Model Results

Training-only five-fold cross-validation selected `RandomForestRegressor` before any holdout evaluation. Its mean CV results were R² **0.833803**, RMSE **253.665987**, and MAE **178.043055**. The predefined full holdout remains the primary evaluation:

| Evaluation | Rows | R² | RMSE | MAE |
| --- | ---: | ---: | ---: | ---: |
| Full holdout | 11,432 | 0.841877 | 252.270119 | 177.562609 |
| Non-overlap sensitivity subset | 11,401 | 0.842473 | 251.476988 | 177.144459 |

For the sensitivity check, 31 eligible holdout rows shared a UID with eligible training data, 31 had an exact approved predictor match, and their union was 31 rows; rows meeting both conditions are counted once. The same already-fitted pipeline and existing predictions were evaluated after excluding that union. The small observed differences are descriptive evidence that this exact-overlap exclusion does not materially change these results, but the subset is not a new independent external test set. The historical and modern results are not directly comparable because their methodology differs.

The validated run used Python 3.12.13, NumPy 2.5.3, Pandas 3.0.6, and Scikit-learn 1.9.1. See [`docs/validated_environment.md`](docs/validated_environment.md) for the focused reproducibility record.

## Running the Notebook

1. Clone and enter the repository:

   ```bash
   git clone https://github.com/Saurabhzambare/Real_Estate_Capstone.git
   cd Real_Estate_Capstone
   ```

2. Create and activate a virtual environment:

   ```bash
   python -m venv .venv
   source .venv/bin/activate
   ```

   On Windows PowerShell, use `.venv\Scripts\Activate.ps1` instead.

3. Install the dependencies:

   ```bash
   python -m pip install -r requirements.txt
   ```

4. Launch Jupyter:

   ```bash
   jupyter notebook
   ```

5. Choose the appropriate notebook: `real_estate_capstone.ipynb` is the preserved historical workflow, while `real_estate_modeling_modernized.ipynb` is the modern modeling workflow. The historical notebook should be run from `notebooks/`; the modernized notebook supports execution from either the repository root or `notebooks/`.

6. Run the reusable-code tests from the repository root:

   ```bash
   pytest -q
   ```

The historical notebook is an archived learning artifact created with older library versions and has intentionally not been comprehensively rewritten. Its legacy APIs may still require updates with modern packages; the separate modern modeling notebook is the validated Step 67 workflow.

## Historical Workflow Limitations

- The test feature matrix is scaled with a separate `fit_transform()` rather than transformed with the scaler fitted on the training data.
- The section described as state-level modeling filters rows using `COUNTYID` rather than `STATEID`.
- Model validation is limited, and there is no cross-validation pipeline.
- Legacy APIs such as `seaborn.distplot()` are used.
- Some dependency installation commands are embedded directly in notebook cells.

These issues belong to the preserved historical artifact. The modernized companion corrects the preprocessing, validation, and state-grouping methodology without silently rewriting the original notebook.

## Modern Workflow / Repository Limitations

- The dataset is older, and its original external source, collection process, and some definitions remain unclear.
- The modern feature choices and results have limited business/domain validation and no external validation dataset.
- Random K-fold validation may not represent geographic or temporal distribution shift.
- The tracked files contain 123 UID values shared across train and holdout, and 177 holdout rows have a modeling-feature vector also present in training. This may weaken holdout independence; the audit does not alter the splits or influence model selection.
- There is no production deployment, monitoring, or prediction-uncertainty workflow.
- Package versions remain unpinned and have not been validated across multiple runtimes.
- The historical Tableau Public link's current availability has not been verified.
